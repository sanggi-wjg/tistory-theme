## 축 1 — 상위 규범 충돌

`DECISIONS.md`와 `DESIGN.md`가 상위 규범이다(CLAUDE.md). 코드가 그것과 다르면
**둘 중 하나는 틀렸고, 어느 쪽인지 정하는 것은 리뷰의 일이 아니라 문서의 일이다.**

| 확인 | 어떻게 |
|---|---|
| 새 색·크기·간격 리터럴 | `DESIGN.md` 토큰 표에 있는 값인가. 없으면 왜 새로 만들었는가 |
| 사다리에 칸을 더했는가 | 한 곳에 쓰려고 토큰을 늘리지 않는다 — 결정 37이 `#1f1f1f`을 거절하고 `--canvas-soft-2`를 쓴 이유 |
| 문서에 **하지 말라고 적힌 것**을 했는가 | 했다면 문서가 **같은 브랜치에서** 갱신됐는지 확인한다. 코드만 바뀌면 다음 사람이 문서를 믿는다 |
| 결정을 뒤집었는가 | 뒤집었으면 새 결정 번호가 있어야 한다. **근거 없이 뒤집힌 결정이 가장 비싸다** |
| 규범이 틀렸다는 근거 | "재보니 틀렸다"는 정당한 근거다. **재지 않고 뒤집은 것**만 차단한다 |

**판정 기준**
- 문서와 다른데 문서가 안 바뀜 → **차단**
- 문서를 같은 브랜치에서 고쳤고 근거(실측)가 있음 → 통과
- 근거가 취향("이게 더 예쁘다")뿐 → **경고**, 사용자 판단으로 넘긴다

## 축 2 — 조용히 실패하는 결함

이 도메인에는 컴파일러가 없다. **에러를 내지 않는 실패**만 여기서 잡을 수 있다.

### 특이도

이 저장소가 **네 번** 진 자리다(결정 32·35·36-b, 그리고 `.contents_style a`).

- 티스토리 시트를 덮는 규칙인가 → 상대 선택자보다 **반드시 크게** 만들었는가.
  같으면 순서 싸움이고 순서는 티스토리가 정한다
- 속성 선택자를 뗐는가 → `[data-ke-size]`를 떼면 클래스 칸이 하나 줄어 진다
- 본문 안에서 `.contents_style a`(0,1,1)와 겨루는 규칙인가 → 클래스 둘(0,2,0)이 필요하다
- `!important`를 새로 넣었는가 → 이 저장소는 `!important` 대신 **치환자를 바꿔** 원인을
  없앤 전례가 있다(결정 31). 원인이 남아 있는데 덮고 있지 않은지 본다

### 셀렉터·훅 정합성

**생산자와 소비자를 같이 연다.** 한쪽만 봐서는 못 잡는다.

| 바뀐 것 | 같이 열 것 |
|---|---|
| `skin.html`의 class·data 속성 | `style.css` 선택자, `script.js` 셀렉터 |
| JS가 만드는 새 DOM | 그 클래스를 받는 CSS 규칙이 있는가, `docs/hooks.md`에 등재됐는가 |
| CSS 선택자 이름 | 마크업이 정말 그 이름을 내는가 (**부분일치인가 정확일치인가**) |
| 치환자 | `data/substitutions.json` 화이트리스트, 그리고 그 페이지 영역에서 유효한가 |

### 테마 한쪽만 깨지는 것

**라이트가 멀쩡한 것은 근거가 아니다.** `#333` on 흰 배경은 12.63:1이다.

- 새 색이 **세 면**(`--canvas`·`--canvas-soft`·`--canvas-soft-2`) 전부에서 AA인가.
  이 저장소는 흰 캔버스만 보고 토큰을 정했다가 **두 번** 데었다(`--ink-mute`, `--link`)
- 미디어쿼리나 `[data-theme]` 블록 **안에서 처음 정의된** 색이 있는가 → 버그
- 굵기·크기처럼 **색이 아닌** 것을 덮는가 → 두 테마 다 멀쩡해 보여서 더 안 보인다(결정 36-b)

### JS 열화 경로

- 이 모듈이 실패해도 본문을 읽을 수 있는가
- 기본값이 "감춤"인가 → JS가 안 돌면 영영 안 보인다. 카테고리 접기가
  **기본을 펼침으로 둔** 이유가 이것이다
- 두 모듈이 같은 것을 각자 세는가 → 번호가 어긋나도 화면에는 신호가 없다(결정 38)

## 축 3 — 검사가 이 변경을 볼 수 있는가

**가장 중요한 축이고, 가장 건너뛰기 쉽다.** 린트가 초록불이면 지나가고 싶어진다.

CLAUDE.md 「핵심 위험」: "검증 도구가 통과 신호를 위조한 적이 다섯 번 있다"(횟수·목록은 그쪽이 정본).
- 프리뷰가 영역 중첩 규칙을 몰랐다
- 카테고리 치환자 두 종류를 같은 마크업으로 그렸다
- 티스토리 시트를 싣지 않아 특이도 싸움이 재현되지 않았다
- 댓글 수 치환자를 세 영역 모두 숫자로 채워 "값이 비는" 조건을 그리지 않았다
- `test:hooks`가 실제 마커를 읽어 리뷰 직후엔 차단 케이스가 전부 통과했다

**전부 "검사 통과 + 프리뷰 정상"이었다.**

물을 것은 하나다 — **이 변경이 잘못됐다면, 어떤 검사가 빨간불을 켜는가?**

| 답 | 판정 |
|---|---|
| 이름을 댈 수 있는 린트 규칙이 있다 | 통과 |
| 프리뷰에서 눈으로 봤고, 프리뷰가 그 조건을 싣는다 | 통과 |
| 프리뷰에서 봤지만 프리뷰가 그 조건을 재현하는지 모른다 | **경고** — 무엇을 못 보는지 적는다 |
| **아무 검사도 안 켜진다** | **차단** — 검사를 먼저 만든다. 결정 35·36-b가 `TIS003`·`TIS004`를 낸 이유다 |

프리뷰가 재현하지 **못하는** 것들(알아 두면 오판을 줄인다):
- 댓글·방명록 — 티스토리 React 런타임이라 원리적으로 불가
- 실제 글 275편의 인라인 오염 조합 — 픽스처는 표본이다
- 모바일웹 전환, 광고 삽입 위치, 검색 색인

## 축 4 — 문서 동기화

코드만 바뀌고 문서가 안 따라오면, **다음 세션은 문서를 믿고 틀린다.**

| 바뀐 것 | 따라와야 할 곳 |
|---|---|
| 확정된 판단 | `DECISIONS.md` — 새 번호 + 근거. 번호는 재사용하지 않는다 |
| 토큰·컴포넌트·티스토리 고정 마크업 대응 | `DESIGN.md` 해당 절 |
| JS가 만드는 DOM, 상태 클래스, 마크업 훅 | `docs/hooks.md` §5·§6·§7·§8 |
| TODO 항목을 닫았다 | `TODO.md` — 항목을 지우고 **닫힌 항목** 표에 어디로 갔는지 |
| 린트 규칙을 냈다 | `/skin-qa-check` 규칙 목록 |
| 실측 수치가 바뀌었다 | `DECISIONS.md` §3, `data/*.json` |

**번호로 식별하는 목록**(`DECISIONS.md` 미결, `TODO.md`)에 항목을 **더할** 때는
번호가 아니라 슬러그를 쓴다 — 동시 작업이 겹친 전례가 세 번 있다.
기존 번호는 다른 문서가 참조하므로 그대로 둔다.

## 축 5 — 일반 코드 품질

**빌트인 `/code-review`에 위임한다.** 정확성 버그, 중복, 불필요한 복잡도는
범용 도구가 더 잘 본다. 결과를 받아 `_workspace/pr-review.md`에 합친다.

위임하고도 직접 볼 것 하나 — **범위.** diff에 이 작업과 무관한 변경이 섞여
있는가. 섞여 있으면 경고로 올린다. 사이클 하나에 브랜치 하나가 이 저장소의 규칙이다.

## 지적 쓰는 법

> ❌ "스타일이 안 먹을 것 같다"
>
> ✅ "`src/styles/content.css:77`의 `.contents_style .heading-anchor`는 (0,2,0)이라
> 같은 파일 `:107`의 `.contents_style a`(0,1,1)를 이긴다. 다만 티스토리
> `content.css`에 `#tt-body-page .contents_style a`가 있으면 (1,1,1)로 진다 —
> `data/tistory-hardcoded-colors.json`에 그런 규칙은 없다. **통과**"

- **파일:라인**을 단다. 클릭해서 갈 수 있어야 한다
- **어긋나는 두 쪽을 모두** 쓴다. 한쪽만 쓰면 어디를 고칠지 모른다
- **근거를 단다** — 결정 번호, 실측 수치, 특이도 계산
- 못 본 것은 **못 봤다고** 쓴다. "아마 괜찮다"는 통과가 아니라 경고다
