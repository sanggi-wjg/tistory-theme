# 블로그 콘텐츠 실측

이 프로젝트의 설계 결정은 거의 전부 실측에서 나왔다. **잘못 집계한 수치는 조용히 잘못된 CSS가 된다.**

## 실행

```bash
# 목록만 (빠르다, 14페이지)
python3 .claude/skills/blog-census/scripts/census.py --posts

# 본문까지 (느리다, 275편 — 인라인 스타일·코드블록 집계에 필요)
python3 .claude/skills/blog-census/scripts/census.py --posts --bodies

# 본문 일부만 맛보기
python3 .claude/skills/blog-census/scripts/census.py --posts --bodies --limit 50
```

## 산출물

| 파일 | 내용 | 쓰는 곳 |
|---|---|---|
| `data/posts.json` | 전수 목록 (제목·날짜·카테고리·썸네일·URL) | 프리뷰 픽스처 |
| `data/categories.json` | 카테고리별 집계 (하위 + 상위) | 기본이미지 규칙, 린트 BND003 |
| `data/inline-styles.json` | 인라인 색·배경·폰트, 코드블록 실태 | **린트 INL001** — 보정 규칙 커버리지 검사 |

`--bodies` 없이 돌리면 `inline-styles.json`은 갱신되지 않는다.

## 집계에서 반드시 지킬 것

여기 적힌 것들은 전부 **이 프로젝트에서 실제로 틀렸던 것**이다 (`DECISIONS.md` §5).

| 함정 | 옳은 방법 |
|---|---|
| RSS로 전수를 세려 함 | RSS는 **최신 50편만** 준다. 목록 페이지 14장을 훑어야 275편이 나온다 |
| 표본을 전수처럼 보고 | 집계 범위를 항상 명시한다. "대표이미지 80%"가 전수로는 45.1%였다 |
| 본문 래퍼 정확일치 | `<div class="[^"]*contents_style[^"]*">`. `class="contents_style"`로 찾으면 **오래된 글 33편이 조용히 누락**된다 |
| 파싱 실패를 0으로 착각 | 파싱 성공 건수를 전체와 대조한다. 스크립트가 `[본문 미발견]`을 출력하면 원인을 밝힌다 |
| 코드 내용을 스타일로 오인 | `<code>` 내용을 먼저 제거한다. 파이썬 코드의 `color = green`이 섞인다 |
| `og:image` 유무로 대표이미지 판정 | 없으면 티스토리 **기본 OG 이미지**로 떨어진다. 목록의 `class="thumb"` 유무가 정확하다 |
| 평균만 보고 | 중앙값·최대·분포를 함께 본다. "전체 45%지만 최신 20편은 85%"가 여기서 나온다 |

## 결과가 설계에 미치는 영향

수치가 바뀌면 **어디를 고쳐야 하는지 지목**한다.

| 변화 | 영향 |
|---|---|
| 새 인라인 색 등장 | `DESIGN.md` §5.2 열거 목록 + `src/styles/content.css` 보정 규칙 |
| 새 카테고리 추가 | 기본이미지 SVG + `src/styles/` 접두 선택자 (린트 BND003이 잡는다) |
| 최신 20편 대표이미지 비율 하락 | 홈 그리드 전제가 흔들린다. `DECISIONS.md` 재검토 |
| 제목 길이 증가 | 홈 카드 클램프 줄 수 |
| 코드블록 언어 라벨 신뢰도 변화 | 하이라이팅 정책 |

## 재실행 시

이전 `data/posts.json`과 비교해 **차이만 보고**한다. 스크립트가 이전 총계를 함께 출력한다. 전체를 다시 나열하지 않는다 — 새 글 수, 새 인라인 색, 새 카테고리가 핵심이다.

## 마크업이 바뀌었을 때

스킨을 교체하면 목록 페이지 구조가 달라져 파싱이 실패한다. 스크립트는 `<div class="post">`를 기준으로 자른다. **임의로 고치지 말고 새 구조를 보고**한 뒤 지시를 받는다 — 잘못 고치면 조용히 틀린 수치가 나온다.
