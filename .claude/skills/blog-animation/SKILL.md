# 블로그 설명 애니메이션

글 본문에 들어갈 움직이는 도식을 만든다. **결과물은 GIF 한 장**이고, 원본 HTML은 고칠 때를 위해 같이 둔다.

## 왜 GIF인가

티스토리 글 본문의 HTML 모드에 `<canvas>`·`<script>`를 넣으면 **처음 저장할 때는 돌지만, 기본 모드로 갔다
돌아오면 망가진다**(2026-10-08 사용자 실측, `DECISIONS.md` §2 「반드시 알아야 할 제약」). 글을 한 번 고치다
데모가 조용히 사라질 수 있다. 이미지는 에디터가 손대지 않고, RSS·피드처럼 JS가 안 도는 곳에서도 움직인다.
대신 상호작용(토글·슬라이더)은 포기한다 — 대비할 두 상황은 **파일을 둘로** 나눈다(예시의 `deadlock`/`sorted`).

본문 `<script>`나 스킨 훅(`script.js`가 본문의 표식을 찾아 그리는 방식)으로 바꾸려면 결정이 필요하다 — 이 스킬의 범위가 아니다.

## 절차

### 1. 장면을 단계 목록으로 쓴다

그리기 전에 **단계 표**부터 사용자와 맞춘다. 단계마다 *누가 · 무엇을 · 캡션 한 줄*. 대비가 핵심인 개념(나쁜 예 ↔ 좋은 예)은
장면을 두 파일로 나눈다.

**캡션의 사실 주장은 공식 문서로 확인한다.** 첫 데드락 컷은 「InnoDB가 B를 롤백」이라고 단정했는데, 실제로는 InnoDB가
*변경한 행이 적은 쪽*을 고른다(MySQL 8.0 「Deadlock Detection」) — 사용자가 「B가 무조건 끊기나?」로 잡았다. 장면을 위해
한쪽을 고른 것이면 캡션에 「여기선 B」처럼 그것이 예시임을 드러낸다.

### 2. 템플릿을 복사해 장면만 바꾼다

```bash
cp .claude/skills/blog-animation/assets/template.html posts/assets/<슬러그>.html
```

파일은 「장면」과 「엔진」 두 칸이다. **장면 칸만 고친다** — `initial()`(처음 상태), `STEPS`(단계), `draw(r, t)`(그리기).
엔진 칸에 계약·속도·테마·조작 막대가 있다. 실제로 만든 예시 두 개가 `assets/examples/`에 있다 — 행 10개·레인 2개·대기 화살표·
고리 강조·롤백 취소선까지 쓰는 복잡한 장면이 필요하면 거기서 시작한다.

원본 HTML과 GIF는 글 초안 옆 `posts/assets/`에 둔다 — 나중에 캡션·속도를 고쳐 다시 구울 원본이다.

### 3. 계약 검사 → 정지 장면으로 직접 본다

```bash
node .claude/skills/blog-animation/scripts/render-gif.mjs posts/assets/<슬러그>.html --check
node .claude/skills/blog-animation/scripts/render-gif.mjs posts/assets/<슬러그>.html --stills 3,9.5,18
```

`--stills`는 `<슬러그>.still-<t>.png`를 남긴다. **핵심 장면마다 Read로 열어 본다** — 글자 잘림·겹침, 화살표가 맞는 칸을
가리키는가, 캡션이 한 줄에 들어가는가. 여러 장은 `ffmpeg -i a.png -i b.png -filter_complex vstack=inputs=2 sheet.png`로 묶어
한 번에 본다. 확인이 끝나면 still PNG는 지운다.

### 4. 사용자에게 속도를 보여 준다 — 굽기 전에

```bash
open -a "Google Chrome" posts/assets/<슬러그>.html
```

**나는 움직임의 속도감을 판단하지 못한다** — 프레임을 낱장으로 볼 뿐이다. 처음 컷은 사용자가 「빠르다」고 했고 절반 → 1.5배로
맞췄다. 그래서 템플릿의 `SLOW`가 **1.5**에서 출발한다. 속도 요청은 `SLOW` 한 줄로 받는다(`STEPS`의 `d`는 기준 박자). 화면
아래 슬라이더로 사용자가 장면을 짚어 말할 수 있다.

### 5. 굽는다

```bash
node .claude/skills/blog-animation/scripts/render-gif.mjs posts/assets/<슬러그>.html
# → posts/assets/<슬러그>.gif   (옵션: --fps 12 --theme light --scale 1.5 --out 경로)
```

기본값은 사용자가 정한 것과 실측에서 나왔다.

| 값 | 기본 | 근거 |
|---|---|---|
| 테마 | `light` | 사용자 결정(2026-10-08). GIF는 한 장이라 블로그 다크모드를 못 따라간다 |
| 배율 | 1.5 → 760×400이 1140×600 | 레티나에서 흐리지 않게. 2배면 파일이 커진다 |
| fps | 12 | 나타나기·점선 흐름에 충분. 28초 한 편이 340프레임 · 약 520KB |
| 색 | 128색 팔레트, 디더링 끔 | 평면 도형이라 면이 깨끗하고 작다 |

끝나면 결과 줄(프레임 수·길이·크기)을 보고에 옮기고, GIF에서 프레임 하나를 뽑아(`ffmpeg -ss <초> -i x.gif -frames:v 1 f.png`)
HTML과 같은 그림인지 본다.

### 6. 올리기는 사용자 몫이다

**티스토리에 올린 GIF가 애니메이션을 유지하는지는 아직 확인하지 않았다(2026-10-08).** 첫 업로드 때 사용자에게 확인을 받고,
결과를 이 줄에 적는다.

## 캡처 계약

`render-gif.mjs`는 페이지를 `?capture=1&theme=…&t=…`로 열고 아래를 확인한 뒤에만 찍는다. 하나라도 어긋나면 GIF는
**에러 없이 틀린 그림**이 된다 — 이 저장소의 「조용히 실패한다」와 같은 부류다.

| 계약 | 어기면 |
|---|---|
| `window.__render(t)`·`__total`(초)·`__size`([w,h]) | 찍을 수 없다 |
| 그림이 **t만의 함수** — `Date`·`Math.random`·이전 프레임 상태 금지 | 프레임마다 다른 장면이 섞인다 |
| 움직임을 **CSS animation/transition·SMIL에 맡기지 않는다** — 점선 흐름도 `stroke-dashoffset`을 t로 민다 | 브라우저에서는 움직이는데 GIF에서는 멈춘다 |
| `?capture=1`이면 `body.capture`로 조작 막대를 숨긴다 | 막대가 GIF에 찍힌다 |

엔진이 매 프레임 `initial()`에서 단계를 다시 쌓는 것이 순수성을 지키는 방식이다 — 상태를 프레임 사이에 들고 가지 않는다.

**`render-gif.mjs`의 검사를 고치면 `scripts/test-contract.mjs`를 돌린다.** 템플릿에서 계약을 하나씩 깬 사본 다섯 개가 전부
실패하고 원본·예시가 전부 통과해야 한다. 처음 짠 검사는 `Math.random`과 CSS transition을 **통과시켰다** — t=0 한 점만 보고
`getAnimations()`만 셌기 때문이다.

## 그리기 규칙

- **색은 의미로 쓴다** — 주체 둘은 `--a`(파랑)·`--b`(호박), 실패·데드락은 `--err`, 성공·커밋은 `--ok`, 나머지는 회색 사다리.
  값은 `DESIGN.md` 토큰이다. 주체가 셋 이상이면 색을 늘리기 전에 레인 배치로 구분할 수 있는지 먼저 본다.
- **캡션이 장면을 끌고 간다** — 아래 캡션 막대 한 줄. 결정적 순간(데드락·커밋)만 `tone`으로 색을 입힌다.
- **새로 생긴 것만 나타나게** — 단계 `fn`에서 `s.fresh`를 세우고 `draw`에서 `ease(p * 3)`으로 페이드. 전부 움직이면 어디를 볼지 모른다.
- 판은 760×400(viewBox). 바꾸면 `W`·`H`·viewBox를 같이 바꾼다 — 캡처 크기는 `__size`에서 온다.
- **모바일에서는 글자가 읽히지 않는다 — 아직 풀지 않았다.** 390 폭의 본문 칸이 285px(프리뷰 실측)라 판이 0.375배로 줄고
  11px 라벨이 약 4px가 된다(이슈 #103 `anim-mobile-legibility`). 정하기 전까지는 GIF를 넘길 때 이 사실을 사용자에게 알린다.

## 하지 않는 것

- **프레임마다 Chrome을 새로 띄우지 않는다.** 처음에 그렇게 했다가 340장에 10분이 넘었고 338장에서 멈췄다. `render-gif.mjs`는
  Chrome 하나를 CDP로 붙잡고 `__render(t)`만 바꿔 찍는다(한 편 약 17초).
- GIF를 다크로 구우려면 `--theme dark`. 다만 블로그는 라이트·다크를 오가므로 한 장으로는 한쪽에서 어색하다 — 기본은 라이트다.

## 필요한 것

Chrome(`/Applications/Google Chrome.app`, 다른 경로는 환경변수 `CHROME`), Node 22 이상(내장 WebSocket), ffmpeg(`brew install ffmpeg`).
없으면 스크립트가 무엇이 없는지 말하고 멈춘다.
