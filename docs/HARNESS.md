# 하네스

이 저장소에서 Claude Code가 티스토리 스킨을 만들고 검증하는 장치 — 에이전트·스킬·Claude Code 훅·검사 사슬·CI — 의 문서다.
**매 세션 지킬 규칙은 [CLAUDE.md](../CLAUDE.md) 「하네스」에 있고, 여기에는 그 규칙의 근거가 된 사고와 변경 이력을 둔다.**
CLAUDE.md는 세션마다 통째로 맥락에 실리므로 기록이 아니라 지시만 담는다.

- **하네스를 바꾸면 아래 「변경 이력」 맨 위에 행을 더한다** — 날짜 · 변경 내용 · 대상 · 사유. 에이전트·스킬·훅·워크플로우를 더하거나 빼면 「구성」 표도 같이 고친다.
- **위조된 통과 신호의 횟수는 이 문서 「핵심 위험」이 정본이다.** 다른 문서는 횟수를 옮겨 적지 않고 여기를 가리킨다.

⚠ 이 문서의 「훅」은 **Claude Code 훅**(`.claude/hooks/`)이다. 스킨 마크업 훅 계약은 [docs/hooks.md](./hooks.md)이고, 둘은 서로 참조하지 않는다.

## 핵심 위험

첫째 위험은 이 도메인 자체다 — 티스토리에는 컴파일러가 없어 치환자 오타·선택자 불일치·`null` 셀렉터가 **셋 다 조용히 실패한다.**
그에 대한 규칙 셋(조용히 실패한다 · 이름으로 저장소 전체를 훑는다 · 검사 초록불을 의심한다)은 CLAUDE.md 「하네스」에 있고,
여기는 나머지 둘의 규칙이 나온 사고다.

### 두 번째 위험 — 결정이 무효로 만든 문장을 같이 못 고친다

2026-08-27 셀프 리뷰에서 셋이 나왔다. 결정 36이 `--wrap`을 1520으로 올려 놓고
결정문에 안 적어 **정본 두 문서가 서로 다른 값**을 말했고, 결정 44는 `--error`의
사용처를 옮기며 "이제 쓰는 데가 없다"를 세 곳에 적었는데 생성기 안의 사용처를
못 봤으며, 결정 29가 뒤집은 전제를 요구하는 린트가 **주석 한 줄에 매달려** 조용히
살아 있었다. **셋 다 `npm run check`가 원리적으로 못 본다** — 린트는 "규칙이
있는가"를 보고 이건 "**전에 적은 문장이 아직 참인가**"다.
상수·토큰·치환자를 바꿨으면 **그 이름으로 저장소 전체를 훑는다.** `src`만으로는
부족하다 — 생성기(`scripts/build.mjs`)가 문자열로 쓰는 사용처는 `dist`에만 있다.

### 검증 도구가 통과 신호를 위조했다

**검증 도구가 통과 신호를 위조한 적이 열두 번 있다** (이 문단이 횟수의 정본이다 — 다른 문서는 횟수를 옮겨 적지 말고 여기를 가리킨다. 옮긴 사본은 2026-09-15 점검에서 넷이 뒤처져 있었다). 프리뷰가 영역 중첩 규칙을 몰랐고, 카테고리 치환자 두 종류를 같은 마크업으로 그렸고, 티스토리 시트를 실지 않아 특이도 싸움이 재현되지 않았고, **댓글 수 치환자를 세 영역 모두 숫자로 채워 "값이 비는" 조건을 한 번도 그리지 않았으며**(결정 42), **`test:hooks`가 실제 저장소의 리뷰 마커를 읽어 리뷰 직후엔 차단 케이스 7개가 전부 통과했다**(2026-08-27, 아래 「변경 이력」). 그 뒤 프리뷰가 같은 부류로 넷을 더 위조했다 — 페이징 번호를 맨 숫자로 치환해 현재 페이지 표시와 `no-more-*`를 안 그렸고(결정 53), 이미지블록에 `srcset`을 안 실어 라이트박스가 축소본을 띄우는 것을 못 봤고(결정 56), 빈 메뉴를 빈 문자열로 넣어 라이브에서 한 번도 참이 된 적 없는 `:empty` 가드가 멀쩡해 보였고(결정 57), 카테고리 앵커에 새 글 아이콘을 안 그려 배지가 밀리는 조건을 못 봤다(결정 58). 또 본문 픽스처에 글쓴이 브라우저의 번역 확장이 남긴 `#gtx-trans`(인라인 absolute 좌표)가 없어 모바일 가로 넘침을 못 봤다(결정 61). 열한째는 티스토리 **툴바**를 그리지 않아 1261~1868px에서 툴바가 테마 토글을 88% 덮는 것을 못 봤다(결정 59 — 사용자 화면이 그보다 넓어 사람 눈도 놓쳤다). 열두째는 티스토리 **phocus 이미지 뷰어**를 싣지 않아 이미지를 누르면 뷰어가 두 겹 뜨는 것과, 전역 `scroll-behavior: smooth`가 phocus의 스크롤 복귀를 1.5초 굴러가게 만드는 것을 못 봤다(결정 60 — 그 흉내를 넣은 첫 판조차 클래스를 동기로 붙여 키보드 경로의 두 겹을 통과시켰고, 라이브 글에 브랜치 빌드를 끼워 넣어서야 잡혔다). 다섯째(`test:hooks`)만 게이트를 통과한 직후 `npm run check`를 다시 돌리다 드러났고, 나머지 열하나는 전부 라이브에서만 드러났다. **린트·프리뷰가 통과하면 "그 검사가 실제 조건을 재현하는가"부터 의심하고, 재현하지 않으면 검사부터 고친다.**
